## ✅ Что реализовано (Выполнение)

### 1. База данных SQLite
- Создан файл базы данных `tickets.db` (подключается через библиотеку `sqlite3`).
- Создана таблица `tickets` со следующими полями:
  - `id` (INTEGER, PRIMARY KEY, AUTOINCREMENT) — уникальный номер.
  - `event_id` (INTEGER) — ID мероприятия.
  - `type` (TEXT) — тип билета (`general`, `vip`).
  - `price` (REAL) — цена билета.
  - `remaining` (INTEGER) — остаток мест.
- При первом запуске сервер автоматически добавляет тестовые данные (3 билета).

### 2. Реализованные API-маршруты (CRUD)
| Метод | Маршрут | Описание |
|-------|---------|----------|
| **GET** | `/api/tickets` | Получить список всех билетов. |
| **GET** | `/api/tickets?event_id=7` | Получить билеты только для конкретного события (query-фильтрация). |
| **POST** | `/api/tickets` | Создать новый билет (принимает JSON: `event_id`, `type`, `price`, `remaining`). |
| **DELETE** | `/api/tickets/:id` | Удалить билет по его ID. |
| **PUT** | `/api/tickets/:id/buy` | Эмуляция покупки билета (уменьшение `remaining`). |

### 3. Реализация транзакций (Логика покупки)
Маршрут `PUT /api/tickets/:id/buy` работает по следующему алгоритму:
1. Открывается транзакция (`BEGIN TRANSACTION`).
2. Проверяется текущее значение `remaining`.
3. Если после вычета запрошенного количества (`count`) остаток становится **меньше нуля**:
   - Выполняется **откат транзакции** (`ROLLBACK`).
   - Возвращается статус **`400 Bad Request`** с сообщением: `Недостаточно билетов`.
4. Если остаток достаточный:
   - Обновляется значение `remaining` в базе (`UPDATE`).
   - Транзакция фиксируется (`COMMIT`).
   - Возвращается успешный ответ с новым остатком.
